\begin{abstract}
Frontier-scale Large Language Models (LLMs) demonstrate high accuracy in complex tasks but remain computationally expensive and slow. Conversely, compact models are efficient but often brittle, struggling with self-correction and sensitivity to prompt phrasing. This project investigates Automatic Prompt Optimization (APO) as a bridge to enhance compact models for verifiable tasks. Using the GEPA (Genetic-Pareto) framework, we optimize prompts for two distinct tasks: SQL Synthesis (Example Generation) and SQL Analysis (Counterexample Discovery). We introduce a novel contribution, ``Hyper-Reflection,'' which utilizes frontier models to optimize the reflection mechanism within GEPA itself. Furthermore, we identify and resolve a critical ``thinking truncation'' failure mode in compact models performing Chain-of-Thought reasoning. Our results demonstrate that APO, combined with extended context windows and Hyper-Reflection, allows a compact \texttt{Qwen3-8B} model to achieve significant performance gains, solving the SQL Synthesis task (100\% success) and reaching 75\% accuracy on the challenging SQL Analysis task, outperforming baselines by 30\%.
\end{abstract}

\begin{IEEEkeywords}
Prompt Optimization, GEPA, SQL Verification, Hyper-Reflection, LLM Reasoning, Chain-of-Thought, Meta-Optimization, Context Window Extension, Knowledge Distillation, Compact Language Models.
\end{IEEEkeywords}

\section{Introduction}

Large Language Models have revolutionized natural language processing, yet a fundamental tension exists between model capability and deployment cost. Frontier models like GPT-4 and Claude achieve remarkable accuracy but require substantial computational resources, while compact models offer efficiency at the expense of reliability. This work addresses a critical question: \emph{Can systematic prompt optimization bridge the capability gap, enabling compact models to approach frontier-level performance on verifiable tasks?}

Prompt engineering has become essential for deploying LLMs effectively, yet crafting optimal prompts remains challenging due to model sensitivity to phrasing and format~\cite{efficient_prompting_survey}. Manual prompt engineering is time-consuming and non-transferable across models or tasks. Automatic Prompt Optimization (APO) addresses these challenges through systematic search over prompt spaces, treating prompts as learnable parameters that can be optimized using feedback from task execution.

We focus on SQL verification tasks---SQL Synthesis (generating query examples with equivalence relationships) and SQL Analysis (discovering counterexamples to query equivalence)---because they provide unambiguous success criteria through database execution. This verifiability enables rigorous evaluation of optimization techniques without human annotation.

Our work builds on GEPA~\cite{agrawal2025gepa}, a reflective evolutionary algorithm that evolves prompt populations using natural language reflection. GEPA's reflection mechanism (Figure~\ref{fig:gepa_reflection}) uses a teacher LLM to analyze task execution feedback and propose improved prompts. A key insight of our work is that this reflection mechanism itself can be optimized.

We introduce \textbf{Hyper-Reflection}, a meta-optimization technique that applies prompt optimization to GEPA's reflection instructions. As illustrated in Figure~\ref{fig:hyper_reflection}, we employ frontier models (Claude Opus, GPT-5, Gemini 2.5, ...) to generate improved reflection templates. This approach embodies Sutton's ``Bitter Lesson''~\cite{sutton2019bitter}: rather than hand-crafting reflection strategies, we leverage computation to discover them automatically.

During our experiments, we uncovered a critical failure mode: \textbf{thinking truncation}. When prompted with sophisticated Hyper-Reflection templates, compact models engaged in extensive Chain-of-Thought reasoning that consumed the entire generation budget, leaving no tokens for the actual answer. Resolving this required extending context windows via YaRN~\cite{yarn2023}, revealing an important principle: \emph{the complexity of optimized prompts must be matched by adequate generation budget}.

The key contributions of this work are:
\begin{enumerate}
    \item \textbf{Hyper-Reflection}: A novel meta-optimization technique that applies prompt optimization to GEPA's reflection mechanism itself, using frontier models to improve reflection instructions (Section~\ref{sec:methodology}).
    \item \textbf{Thinking Truncation Analysis}: Identification and resolution of a critical failure mode where Chain-of-Thought reasoning in compact models consumes the entire generation budget (Section~\ref{sec:overthinking}).
    \item \textbf{SQL Task Benchmarks}: Two verifiable SQL tasks---Synthesis and Analysis---with automated evaluation using database execution feedback (Section~\ref{sec:tasks}).
    \item \textbf{State-of-the-Art Results}: Achievement of 75\% accuracy on SQL Analysis using a compact 8B model, representing a 30-point improvement over baselines (Section~\ref{sec:results}).
\end{enumerate}


\section{Background and Related Work}
\label{sec:background}

Having outlined our contributions, we now situate Hyper-Reflection within the broader landscape of LLM adaptation techniques. Two complementary approaches exist for tailoring LLMs to specific tasks: weight-space adaptation and prompt-space optimization. Our work falls squarely within the prompt-space paradigm, extending it through meta-optimization of the reflection mechanism itself.

\subsection{Weight-Space vs.\ Prompt-Space}

Classical knowledge distillation trains a smaller student to match a teacher's output distribution~\cite{hinton2015distill}, yielding fast inference but requiring gradient access and substantial training data. Parameter-efficient fine-tuning (PEFT) methods reduce this cost by updating only a small fraction of parameters~\cite{ding2023peft}. Prefix tuning~\cite{li2021prefixtuning} learns continuous key-value prefixes injected into Transformer layers, while LoRA~\cite{hu2022lora} inserts low-rank matrices into weight layers. These methods provide a continuous, weight-space analog to discrete prompt optimization~\cite{petrov2024theory}.

In contrast, \emph{prompt-space} methods keep model weights fixed and optimize the conditioning text. Automatic Prompt Optimization (APO) treats prompts, chain-of-thought templates, and demonstrations as learnable parameters. AutoPrompt~\cite{pryzant2023apo} performs gradient-guided token search; APE~\cite{zhou2022ape} uses LLMs to generate and select prompts; OPRO~\cite{yang2023opro} iteratively refines prompts based on feedback. 

% DSPy~\cite{khattab2023dspy} transforms LLM pipelines into optimizable programs with automatic prompt tuning.

Prompt-space methods offer key advantages: they require only black-box API access, work with proprietary models, and produce interpretable, shareable prompts. However, they are limited by context length and may struggle with highly instance-specific reasoning. Retrieval-Augmented Generation (RAG)~\cite{lewis2020rag} addresses instance-specific reasoning by maintaining an external document database; at runtime, a retriever selects relevant evidence that is concatenated into the prompt, allowing the model to condition on facts specific to each query. Chain-of-thought (CoT) prompting~\cite{wei2022cot} takes a complementary approach, allocating context to runtime ``thinking tokens'' that let the model reason step-by-step, while methods like Distilling Step-by-Step~\cite{hsieh2023distilling} train students on teacher-generated reasoning traces.


\subsection{GEPA and Reflective Optimization}

GEPA~\cite{agrawal2025gepa} combines prompt optimization with reflection and evolutionary search. It maintains a population of prompt candidates, executes them on task batches, collects trajectory feedback (including error messages and intermediate reasoning), and uses a teacher LLM to propose improved variants. Candidates are selected via Pareto optimization over accuracy, robustness, and diversity. GEPA achieves approximately 10\% better performance than GRPO-based reinforcement learning~\cite{grpo2024} while using up to 35$\times$ fewer rollouts.

Operationally, GEPA alternates between: (1)~executing prompts and logging trajectories, (2)~aggregating task-specific feedback, (3)~reflecting via teacher LLM to propose mutations, and (4)~updating the Pareto frontier. Our work extends this loop by applying optimization to the reflection mechanism itself.

Related approaches include MIPROv2~\cite{mipro2024}, which uses Bayesian optimization for multi-stage LLM pipelines, and Deep Language Networks~\cite{sordoni2023dln}, which apply variational inference to optimize prompts across stacked LLM layers. Recent work has built upon GEPA: C-Evolve~\cite{li2025cevolve} evolves prompt groups with consensus-based voting; Maestro~\cite{wang2025maestro} jointly optimizes agent graphs and configurations; Feedback Descent~\cite{lee2025feedback} uses pairwise comparisons with textual rationales; and ACE~\cite{zhang2025ace} treats context as an evolving ``playbook.'' Our Hyper-Reflection contribution is orthogonal to these advances and could potentially be combined with them.

\section{Methodology}
\label{sec:methodology}

The core of our methodology is the ``Template Improver'' (Figure~\ref{fig:template_improver}), a meta-prompt designed to improve any instruction template---including GEPA's reflection instructions. The key challenge was creating a template that could improve even itself without confusing the LLM through recursive self-reference.

We employed frontier models (Gemini 2.5, GPT-5, Claude Opus, ...) to rewrite GEPA's default reflection template, treating it as the ``subject template'' to be optimized. This process generated variants such as \texttt{opus1}, \texttt{gemni1}, and \texttt{gpt5think1}, each reflecting the distinct reasoning style of its generating model.

The Template Improver enforces several hard rules to ensure robust operation:
\begin{itemize}
    \item \textbf{Scope restriction:} Modify only the subject template, treating all other text as meta-specification not content for rewriting.
    \item \textbf{Recursion guard:} If the subject template contains ``You are Template Improver,'' treat it as literal text to prevent infinite recursive application.
    \item \textbf{Fact grounding:} Derive domain-specific facts solely from exemplars, inserting TODO markers for missing details rather than hallucinating.
    \item \textbf{Literal preservation:} Preserve text within triple backticks as literal content that should not be interpreted or executed.
\end{itemize}

\subsection{Data Source}

For our experiments, we use a LeetCode SQL dataset containing 23,994 query pairs. Ground truth equivalence was established using VeriEQL~\cite{yang2024verieql}, a bounded verification tool based on SAT solvers that provides formal guarantees about query equivalence within specified bounds. Analysis of the dataset revealed that 33 target queries  (official answers, paired with numerous student attempts) dominated 81\% of the examples, motivating the addition of the SQL Synthesis task to generate more diverse query pairs.

Importantly, our notion of SQL query equivalence follows \emph{bag semantics} (multiset semantics), not list semantics. Under bag semantics, two queries are equivalent if they return the same multiset of rows---duplicates matter, but row ordering does not. This reflects standard SQL behavior where query results are unordered unless an explicit \texttt{ORDER BY} clause is specified. In our evaluation functions (Figures~\ref{fig:synthesis_scoring} and~\ref{fig:analysis_scoring}), we sort results before comparison to ensure that row ordering does not affect equivalence judgments, while preserving duplicate sensitivity.


\section{Task Definitions and Variants}
\label{sec:tasks}

Experiments were conducted using the DSPy framework~\cite{khattab2023dspy}, which provides a declarative interface for specifying LLM-based programs and supports automatic prompt optimization through various backends including GEPA. We define two complementary SQL tasks with automated evaluation.

\subsection{Task 1: SQL Synthesis (Example Generation)}

The SQL Synthesis task generates diverse SQL query examples. Given random nouns as creative prompts, the model must output:
\begin{enumerate}
    \item A valid SQL Schema defining tables and relationships
    \item A base query (\texttt{query\_sql})
    \item An equivalent query (\texttt{equivalent\_query\_sql}) that is structurally distinct but semantically identical
    \item A non-equivalent query (\texttt{nonequivalent\_query \_sql}) that appears similar but yields different results
    \item INSERT statements demonstrating these relationships
\end{enumerate}

Figure~\ref{fig:synthesis_dspy_1} shows the DSPy signature class for the initial generation attempt, specifying the input (random words) and five required outputs. For multi-step variants, Figure~\ref{fig:synthesis_dspy_N} shows the refinement signature, which additionally accepts the previous attempt's outputs and error feedback as inputs. The key difference is that the refinement signature includes \texttt{error} as an input field, allowing the model to address specific failures identified during database execution.

\subsection{Task Variants: Impact of Database Feedback}

Using DSPy signature classes, we defined three variants of LLM interaction flows to test how much structured feedback the model needs:

\begin{itemize}
    \item \textbf{1-Step:} Direct generation (Question $\Rightarrow$ Answer). The model receives the task and produces output with no opportunity for correction.
    \item \textbf{2-Step:} Generation $\Rightarrow$ Evaluation $\Rightarrow$ Refinement. If an error occurs, the model receives database error information and can revise its answer once.
    \item \textbf{3-Step:} Adds an additional refinement loop, giving the model two chances to correct errors based on feedback.
\end{itemize}

These variants allow us to isolate how much improvement comes from structured evaluator feedback versus from prompt optimization itself. For both tasks, the metric is simply \% success over the evaluation set. Success means the database built, queries ran, and the intended equivalence or non-equivalence was demonstrated.

\subsection{Rollout Budget}

While the original GEPA paper utilized budgets of 5,000 to 25,000 rollouts~\cite{agrawal2025gepa}, we observed that significant gains occur early in the optimization process. The performance curves in~\cite{agrawal2025gepa} show that just a small fraction of rollouts at the start are responsible for most gains, with diminishing returns thereafter. We standardized our experiments to use a fixed budget of 500 rollouts to compare methods efficiently. Rollouts measure work done by counting ``task attempts'' during optimization.

\subsection{Hyper-Reflection Experiments}

We evaluated Hyper-Reflection optimized prompts on the single-step variants of both tasks, which ask the LLM the question and check results without giving a second chance to change the answer. This isolates the effect of prompt quality from feedback loops.

To understand the contribution of different components, we tested several reflection prompt variants: the GEPA \texttt{default} prompt, Hyper-Reflection variants generated by frontier models (\texttt{opus1}, \texttt{gemnitf1}, \texttt{gpt5think1}), and an ablated \texttt{default0} prompt. The \texttt{default0} variant was created by removing the feedback-processing instructions from the default GEPA reflection prompt, causing it to ignore task execution feedback entirely. This ablation helps isolate whether performance gains come from the reflection mechanism's ability to analyze feedback or from other aspects of the prompt structure.

The results in Figure~\ref{fig:hr_results} reveal an asymmetry between the two tasks. For SQL Synthesis, GEPA combined with Hyper-Reflection templates proved highly effective: the baseline success rate was 20.00\%, GEPA with the default template raised this to 86.67\%, and the \texttt{gemnitf1} Hyper-Reflection template achieved 98.33\% success. The \texttt{opus1} template achieved 95.00\% and \texttt{gpt5think1} achieved 96.67\%.

However, on the SQL Analysis task, GEPA's default prompt dominates with 70\% task success (25 points above the 45\% baseline). Surprisingly, the Hyper-Reflection prompts underperformed: \texttt{opus1} achieved 62.50\%, \texttt{gemnitf1} achieved only 47.50\% (barely above baseline), and \texttt{gpt5think1} achieved 65.00\%. Even more surprisingly, the ablated \texttt{default0} (which ignores feedback entirely) achieved 67.50\%, close to the default's 70\%.

This raised a critical question: Why did Hyper-Reflection optimized prompts help SQL Synthesis but not SQL Analysis?

    \item GEPA with the default template actually decreased to 55\%, suggesting the default prompt was optimized for shorter contexts and may have become suboptimal when more space was available.

These results validate our hypothesis: Hyper-Reflection prompts induce more sophisticated reasoning that requires adequate generation budget. When context is limited, the sophisticated prompts backfire by consuming tokens on reasoning that never completes. When context is extended, the sophisticated prompts unlock superior performance.

\section{Discussion and Future Work}

\subsection{Key Insights}

Our experiments reveal several important insights about prompt optimization for compact models:

\textbf{Context is Compute.} The ``thinking truncation'' phenomenon demonstrates that the complexity of optimized prompts must be matched by adequate generation budget. This creates a tradeoff between prompt sophistication and inference cost that practitioners must consider. More powerful prompts may require extended context windows, increasing latency and memory requirements.

\textbf{Task-Dependent Optimization.} Hyper-Reflection prompts provided dramatic improvements for SQL Synthesis (98.33\%) but initially failed on SQL Analysis (47.50\%). This asymmetry suggests that optimal reflection strategies may be task-specific, and meta-optimization approaches should account for task characteristics. SQL Synthesis benefits from creative exploration, while SQL Analysis requires systematic edge-case reasoning.

\textbf{Teacher-Student Dynamics.} Using smarter teachers (GPT-4.1-mini, GPT-4.1) helped but did not fully resolve the issues. Surprisingly, the smartest teacher sometimes produced worse results, possibly due to generating prompts that were too sophisticated for the student model. This suggests a ``capability matching'' principle: teacher-generated prompts should be calibrated to the student's capacity.

\textbf{Trade-offs Between Adaptation Approaches.} As discussed in Section~\ref{sec:background}, weight-space distillation yields fast inference but requires training infrastructure; prompt-space optimization requires only black-box access but is limited by context length; runtime reasoning maximizes performance but consumes tokens per query. Our results show that prompt-space methods can achieve substantial gains when combined with context extension, offering a middle ground between adaptation cost and inference efficiency.

\subsection{Future Work}

Several promising directions for future research emerge from this work:

\textbf{Extending Hyper-Reflection to Other Domains.} Our SQL tasks provide clear success criteria through database execution. Extending Hyper-Reflection to other domains with verifiable outcomes (code generation, mathematical reasoning, formal verification) would test its generalizability.

% \textbf{Recursive Template Improvement.} The Template Improver could potentially be applied recursively for multi-level meta-optimization. Measuring the effects of such recursive application---and determining the point of diminishing returns---would advance our understanding of meta-learning in LLMs.

\textbf{Early Stopping for Thinking Tokens.} Implementing early stopping of thinking tokens generation would ensure an answer is always generated, even under token budget constraints. This could be achieved through monitoring the reasoning phase and forcibly transitioning to output when a threshold is approached.

\textbf{Learning from Optimization Trajectories (LEAP).} A potentially transformative direction would be to systematically convert optimization trajectories into training data for prompt optimizers. Methods like GEPA, C-Evolve, Maestro, Feedback Descent, and ACE produce rich trajectories---evolving prompts, pairwise preferences, and textual rationales---that are currently discarded after optimization.

Building on Black-Box Prompt Optimization (BPO)~\cite{cheng2023bpo}, which learns to rewrite user instructions using human preference datasets, one could collect logs from multiple optimizers across benchmarks and base LLMs. These trajectories could be transformed into training examples where a model learns to map from original instructions to improved prompts. Such a system---which we tentatively call LEAP (Learning from Evolved and Augmented Prompts)---would distill the behavior of expensive search-based optimizers into lightweight, deployable prompt rewriters.

Key research questions include: How do synthetic preference data from optimizers interact with human preference datasets? What is the sample efficiency of trajectory-based learning compared to pure search? Can models learn generalizable prompt improvement strategies that transfer across tasks?

\section{Conclusion}

We demonstrated that Automatic Prompt Optimization is a viable strategy for enhancing compact LLMs on verifiable SQL tasks. Key findings include:

\begin{enumerate}

    \item \textbf{Feedback Boosts Success:} Feedback from the database engine (1-step vs 2-step vs 3-step flows) provides immense performance gains. For SQL Synthesis, baseline success increased from 20\% to 93\%; for SQL Analysis, from 45\% to 60\%.
    
    \item \textbf{Thinking Truncation:} We identified a critical failure mode where excessive \texttt{<think>} blocks consume the generation budget, truncating actual answers. This explains why ``smarter'' prompts can paradoxically degrade performance without sufficient context.
    
    \item \textbf{Reasoning Requires Budget:} Complex prompts generated by APO induce long Chain-of-Thought sequences. Standard context limits (8k tokens) can be insufficient; extending context via techniques like YaRN~\cite{yarn2023} is necessary to unlock the performance of optimized prompts.
    
    \item \textbf{Hyper-Reflection Works:} Optimizing the reflection template via frontier models (\texttt{opus1}, \texttt{gemnitf1}) yields superior instructions compared to human-written defaults, provided the student model has the capacity to execute them. The SQL Synthesis task was essentially solved (98.33\% success) after applying Hyper-Reflection.
    
\end{enumerate}

With these optimizations, we achieved a 75\% success rate on SQL Analysis Task (Counterexample Discovery) using a compact 8B model, representing a 30-point improvement over baselines. Our Hyper-Reflection technique offers a general approach for meta-optimization that could be applied to other prompt evolution systems.

YaRN combines NTK-aware interpolation with attention scaling, enabling models to extrapolate beyond their original training length while preserving performance on standard benchmarks.

The key differences in the high context configuration are:
\begin{itemize}

    \item \texttt{rope-scaling}: Applies YaRN with factor 2.75 to interpolate beyond the original 32k position embeddings
\end{itemize}
