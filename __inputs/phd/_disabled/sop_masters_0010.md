Possible Path: Source Code Analysis

This path taps my undergraduate research background in source code analysis. My experience is with source code that implements finite state machines (FSMs) used for autonomous robot control. FSMs are often implemented using switch-default or if-elseif-else syntax structures, and the sequence and nesting of state checks, event checks and guard checks can differ, which makes automatically creating FSM state diagrams tricky. For my undergraduate research I took on the challenge to create a tool for this purpose. Dr.Gabriel Elkaim, who supervised this project, provided guidance on what the diagrams should look like, while I managed the rest, including the tool development and the write-up for IEEE publication. For my Master’s thesis I could add support for additional languages and for automatic generation of additional diagram types such as Harel Statecharts and diagrams that identify programming errors could be created with the help of static
code analysis.

Possible Path: DSL for Generative AI

This path is inspired by my story generator for children which integrates various models like GPT3, MusicGen, StableDiffusionXL, and Suno Bark. It is currently held together by a patchwork of XSLT/Python/Bash scripts. Despite earning applause during demos, this story generator has significant limitations. For example character depiction consistency across pictures remains a challenge. Also using prompt chaining the branching stories (developed one scene at a time) can lose coherence after several steps.

Recognizing these limitations and potential improvements, I aspire to create a Domain-Specific Language (DSL) to seamlessly integrate and control generative models. A well-designed DSL could address: Image Generation: Instead of separately learning how to use stick figures for one AI and scene maps for another, users could learn a single DSL syntax to guide both processes. Music Composition: Musicians could use the DSL to specify song structure, melody lines, or instrument types, ensuring that the AI-generated music aligns closely with their vision. Voice Synthesis: The DSL could allow for detailed control over tone, pitch, and emotion in voice synthesis, useful for creating more nuanced and expressive AI-generated speech. Text Generation: Writers could use the DSL to direct the style, structure, or thematic elements of AI-generated text, enhancing creativity and coherence. Unified Control: Current control methods (like prompt chaining, ControlNet, or input sketches) are fragmented across generative models. A DSL could provide a
standardized way to interact with and guide them.

I envision this DSL as a practical tool, especially for projects like my story generator, which can serve as an ideal test-bed. This approach ensures that the DSL is grounded in real-world requirements. My colleague Luke, who worked closely with me on the story generator, and Dr.Daniel Shapiro, who offered early guidance, will supply letters with additional insights into my role and abilities. While I am the main programmer for this project, it is important to note that I started the story generator project with three colleagues who made equal and invaluable contributions by evaluating many different generative models and integrating just the best few models for us to use. My role was the Flask Web API and Javascript/HTML5 UI and importantly my role was the GPT3 prompts that generate the stories and generate the prompts that get the disparate models to work together. The challenges I faced inspired the desire to have a DSL for this purpose.
